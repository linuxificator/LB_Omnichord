# Dependency assessment: zeroconf

Date: 2026-09-05
Decision: adopt for desktop targets; deliberately defer Android
Owner: OSC DNS-SD discovery adapter
Requirement and code replaced/prevented: portable mDNS probing, conflict-safe
DNS-SD registration and withdrawal
Owning dependency group: desktop runtime

## Functional fit and public API

LB Omnichord needs to publish its already-listening OSC UDP endpoint as the
standard DNS-SD service type `_osc._udp`. `python-zeroconf` provides public
`Zeroconf` and `ServiceInfo` APIs for registration, conflict-safe instance-name
selection and withdrawal. Implementing mDNS packet construction, probing,
multicast-interface handling and record lifetimes locally would duplicate a
substantial network protocol.

Qt supplies the existing portable active-interface inventory used to populate
the service's IPv4 address records. The library remains behind one
application-owned advertiser protocol; OSC parsing, bindings, UI state and
musical state contain no Zeroconf types.

## Maintenance health and release activity

The project published 0.151.3 in 2026, supports current Python releases and
has active release and issue activity. The source repository has multiple
regular contributors and is used by established network-discovery consumers.
The implementation is mature but not treated as infrastructure that may fail
the application: registration remains best-effort behind the live OSC socket.

## Adoption and ecosystem standing

`python-zeroconf` is the established Python implementation of multicast DNS
and DNS-SD and interoperates with Bonjour and Avahi. At review it had more than
700 GitHub stars, more than 200 forks, a long public release history and broad
downstream use. These are supporting maintenance signals, not a security
guarantee.

## Five-platform and packaging evidence

Version 0.151.3 publishes CPython 3.12 wheels verified on 2026-09-05 for:

- manylinux2014 x86_64;
- manylinux2014 aarch64, compatible with the Raspberry Pi builder baseline;
- macOS 11+ arm64; and
- Windows x86_64.

The package has one runtime dependency, the pure-Python universal
`ifaddr==0.2.0` wheel. Desktop builds pin both resolved versions. PyInstaller
collects the complete Zeroconf package and copies both distributions' metadata
and license files. A two-process integration test registers a real OSC input
and discovers its configured name and port over mDNS.

Android is deliberately not supported by this adapter. Reliable mDNS receive
and response on Android needs native multicast lifecycle handling such as a
`WifiManager.MulticastLock`, or a native `NsdManager` bridge, plus manifest and
application-lifecycle work. `python-zeroconf` does not publish Android wheels
or claim Android support. Adding JNI/pyjnius and Android-only lifecycle policy
for a convenience feature would violate the small platform-adapter boundary.
The platform resolver therefore selects an explicit no-op before importing
Zeroconf, and Android continues to receive OSC directly on its configured
address and port.

## License and redistribution obligations

`python-zeroconf` 0.151.3 declares LGPL-2.1-or-later. `ifaddr` 0.2.0 declares
MIT. Desktop packages include `THIRD_PARTY_NOTICES.md` and the unmodified
distribution metadata containing Zeroconf's `COPYING` and ifaddr's
`LICENSE.txt`. The release SBOM identifies each package, exact version,
license and upstream source. Android packages contain neither dependency.

## Security and supply-chain evidence

The exact top-level version and transitive version are constrained. The
packages perform no runtime download or code installation. mDNS advertises
only the configured display name, `_osc._udp`, OSC protocol version, listening
port and active local IPv4 addresses. OSC remains unauthenticated UDP; service
discovery does not widen the socket's configured bind scope, but it makes a
LAN-bound endpoint easier to find. Existing firewall guidance remains
applicable.

## Runtime/thread/real-time impact

Registration never runs on the Qt thread, MIDI thread or AMY audio process.
The advertiser owns one daemon lifecycle worker; the Zeroconf instance owns its
internal event-loop worker. It starts only after the OSC UDP socket binds
successfully, retries quietly if the network is temporarily absent, and
withdraws the service during normal shutdown. Registration failure cannot
change the OSC listener's green/red capability state or delay OSC input.

## Test boundary, migration and exit cost

Unit tests inject an application-owned fake advertiser to prove bind-before-
publish, configuration, opt-out, error isolation and idempotent shutdown.
Adapter tests prove Android selection without importing Zeroconf and desktop
selection of the concrete adapter. The desktop integration contract uses
separate publisher and browser processes and asserts the DNS-SD instance name,
port and non-empty address set.

Removing or replacing the dependency changes only the concrete advertiser,
its packaging inputs and tests. Existing OSC sources, bindings, presets and
UDP input behavior do not migrate.

## Required follow-up and review date

Run all four desktop release builds and their package audits before merging to
`main`. Confirm the macOS bundle contains `_osc._udp` in
`NSBonjourServices`. Reassess Android only if PySide6 exposes a maintained
native NSD/multicast adapter that does not add application-specific lifecycle
code. Review upstream maintenance, licenses and the latest safe compatible
version by 2027-09-05 or sooner after a vulnerability or packaging change.
