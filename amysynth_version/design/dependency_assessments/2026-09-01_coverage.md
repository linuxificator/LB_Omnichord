# Dependency assessment: coverage.py

Date: 2026-09-01
Decision: adopt as a test/quality command
Owner: test and quality requirements
Requirement and code replaced/prevented: subprocess-aware Python branch
coverage for navigation without building a local tracer
Owning dependency group: `requirements-test.txt`

## Functional fit and public API

Coverage.py measures Python line/branch execution, combines parallel data and
can patch Python subprocess creation from checked configuration. This matches
the existing runner, which intentionally executes every test file in an
isolated process. It avoids changing that isolation or implementing tracing,
process coordination and report formats locally. Coverage data is diagnostic;
there is deliberately no repository-wide fail-under percentage.

## Maintenance health and release activity

Coverage.py is Production/Stable and has a long public release history. Version
7.15.4 was released on 2026-08-06 and its official package record declares
support for Python 3.10 through 3.15 (including 3.14 used in development).
The public project credits hundreds of contributors and continues to publish
current compatibility releases.

## Adoption and ecosystem standing

It is the established Python coverage implementation used directly and through
major runners such as pytest tooling. The selected interface is its documented
command/configuration format, not a private Python API.

## Five-platform and packaging evidence

The selected release provides a universal `py3-none-any` wheel and declares
OS-independent support. LB invokes it only in the Linux reusable regression
workflow and local developer environments; it is not imported by portable
runtime code or included in Linux, Raspberry Pi, macOS, Windows or Android
application packages. Package-platform behavior remains covered by the real
native/package suites.

## License and redistribution obligations

Apache-2.0 according to the official PyPI metadata. It is a CI/developer tool,
not redistributed in LB application packages. T24 still records its resolved
test-environment input and license.

## Security and supply-chain evidence

The exact version is pinned in the named test requirements group. It performs
no runtime download and its report input is local Python execution. T24 must
record the selected wheel/hash; automated updates still require review of
subprocess behavior and supported Python versions.

## Runtime/thread/real-time impact

It runs only around tests. It never enters Qt production startup, MIDI readers,
AMY command scheduling or the audio service. Measurement overhead cannot alter
a released application.

## Test boundary, migration and exit cost

The runner uses only the stable `coverage run/combine/json` commands and a
small `.coveragerc`. Removing it leaves all behavioral/native tests intact and
requires deleting one optional runner mode and CI artifact, with no user-data
migration.

## Exact accepted version/range and sources

Accepted: exactly `coverage==7.15.4`.

- [official PyPI release and compatibility metadata](https://pypi.org/project/coverage/)
- [official subprocess measurement documentation](https://coverage.readthedocs.io/en/7.14.1/subprocess.html)

## Required follow-up and review date

Review the pin with T24 or by 2027-03-01, whichever comes first. Keep coverage
as navigation for extracted pure seams; do not replace native/package gates or
add a vanity global threshold.
